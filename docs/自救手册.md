# 自救手册 · 问题导向

> 不要慌。先看是什么问题，按对应步骤走。绝大多数情况 5 分钟内自愈。

---

## 面板打不开 / 显示"路由器SSH断"

**可能的原因**：面板进程挂了、路由器 IP 变了、路由器重启中。

**怎么办**：
1. 关掉面板窗口，重新双击桌面 `路由器面板.bat`
2. 面板启动后等 10 秒，浏览器会自动打开页面
3. 如果还是显示"路由器SSH断"，说明 SSH 真的断了，看下一节

---

## SSH 连不上（`ping` 通但 22 口不通）

**原因**：固件重启后 SSH 解锁清零，自愈脚本正在尝试恢复。

**等一等**：三层自愈（防火墙钩子 + 每分钟 cron + 脚本重试）通常 1-3 分钟内自己拉起。等 3 分钟再试 `Test-NetConnection <IP> -Port 22`。

**如果等不及，远程重新解锁**（不丢配置）：
1. 浏览器登录 `http://<路由器IP>`
2. 从地址栏复制 `stok=` 后面的那串字符
3. 替换下面命令中的 stok 和 IP，逐条执行：

```powershell
$S="<你的stok>"; $B="http://<IP>/cgi-bin/luci/;stok=$S/api/xqsystem/start_binding"
curl.exe -X POST $B -d "uid=1234&key=1234'%0Anvram%20set%20ssh_en%3D1'"
curl.exe -X POST $B -d "uid=1234&key=1234'%0Anvram%20commit'"
curl.exe -X POST $B -d "uid=1234&key=1234'%0Ased%20-i%20's%2Fchannel%3D.*%2Fchannel%3D%22debug%22%2Fg'%20%2Fetc%2Finit.d%2Fdropbear'"
curl.exe -X POST $B -d "uid=1234&key=1234'%0A%2Fetc%2Finit.d%2Fdropbear%20start'"
```

4. 验 22 口：`Test-NetConnection <IP> -Port 22` 应为 True
5. 上面那四行是唯一有效的注入接口。**`arn_switch` 是假接口**（返回 code:0 但不执行），别浪费时间

**能进管理页但不想敲命令**：切换任意防火墙开关（UPnP/DMZ/访客网络 关→开）也能触发自愈。

## 路由器找不到了（`ping` 不通）

**原因**：IP 漂了（路由器重启后 DHCP 可能分配新地址）。

**怎么办**：按 MAC 找 IP

```powershell
# 先用 ping 把网段里的设备刷到 ARP 表
ping 192.168.2.1 -n 1
ping 192.168.2.100 -n 1
ping 192.168.2.106 -n 1
# 然后查 ARP 表找 MAC
arp -a | findstr <路由器机身标签上的MAC>
```

**一劳永逸**：登录 K2P 管理页（192.168.2.1）→ 静态 DHCP 绑定，把路由器 MAC 绑到固定地址（如 192.168.2.106）。从此 IP 不会漂。

---

## 去广告没效果（还是能看到广告）

**原因**：大多数情况是上级路由 DHCP 没把 DNS 指向本机。

**怎么办**：
1. 确认本机地址：`ipconfig /all | findstr "DNS 服务器"`
2. 如果 DNS 不是 `192.168.2.106`，说明当前设备没走路由器去广告
3. 登录 K2P 管理页 → DHCP 设置，把 DNS 改为 `192.168.2.106`
4. 改完后本机 `ipconfig /flushdns` 或重启网卡

**验证去广告生效**：
```powershell
nslookup ad.doubleclick.net 192.168.2.106    # 应回 0.0.0.0
nslookup www.baidu.com 192.168.2.106         # 应正常出地址
```

## 路由器重启后配置丢了

**原因**：/etc 是 ramfs，重启清零。自愈脚本会在开机几分钟内恢复。

**等一等**：auto_ssh.sh 的开机恢复块会自动恢复去广告列表、查询日志、IPv6 拦截、自定义屏蔽。等 5 分钟再看。

**如果等了一直没恢复**：
1. 检查 /data 容量：`df /data`（需 >200K 剩余，卷满会写入静默失败）
2. 手动触发一次恢复：`/bin/sh /data/auto_ssh/auto_ssh.sh`
3. 检查 cron 自愈行：`grep auto_ssh /etc/crontabs/root` — 没有的话重装自愈：`/bin/sh /data/auto_ssh/auto_ssh.sh install`

---

## 固件不小心升级了

**先别慌，不一定封堵了**。先试 SSH 还能不能开：

1. 登录管理页，复制 stok，跑解锁四连 curl（见"SSH 连不上"一节）
2. 跑完 `Test-NetConnection <IP> -Port 22`，通的话直接登录，自愈脚本应该还在
3. 不通的话跑 `一键体检.bat` 确认固件版本

**如果解锁成功**：SSH 和自愈都回来了，不需要降级。但建议关注新固件的变化——这次没封不代表下次不封。

**如果注入被拒（code:1541）且 22 口不通**：新固件确实封了注入路径。唯一出路是降级回 1.0.24（找对应固件版本的降级教程），重新解锁部署。

**预防**：体检已自动检测并关闭自动升级（`otapred.settings.auto=0`）。定期跑 `一键体检.bat` 确认状态。

## SSH 能连上但面板显示"连接失败"

**原因**：面板用的 SSH 密码与路由器当前密码不一致。

**怎么办**：
1. 确认路由器 SSH 密码：`ssh root@<IP>` 试试当前密码
2. 如果改过密码，更新启动器：关面板 → 重新双击 `路由器面板.bat` → 输入新密码
3. 或者：`set ROUTER_PASSWD=新密码` 后再启动面板

## 健康检查显示异常

| 显示 | 含义 | 怎么做 |
|---|---|---|
| ❌ SSH 不通 | 路由器 SSH 挂了 | 看前面"SSH 连不上" |
| ⚠️ 固件非 1.0.24 | 固件变了 | 切勿升级，走"固件升级"处理 |
| ⚠️ 自动升级仍开启 | 未关闭自动升级 | 跑 `一键体检.bat --fix` |
| ⚠️ 自愈未装全 | 自愈脚本缺失 | 重跑 `一键部署.bat` |
| ⚠️ 去广告未加载 | 列表丢了 | 面板里点"更新去广告列表" |
| ⚠️ /data 容量不足 | 卷快满了 | 清理 /data 下无用文件 |
